# 支付超时诊断手册

本文提供通用处理规则；具体订单状态和支付日志必须通过查询工具核实。

## E_PAY_TIMEOUT

`E_PAY_TIMEOUT` 表示支付请求等待网关响应超时。超时本身不能证明付款已经扣款、未扣款或最终交易失败，也不能直接归因于余额不足。需区分系统记录的订单/支付状态与渠道最终结果。

## 核实流程

1. 使用 `order_query` 查询目标订单，核对订单号、订单状态、支付状态和错误码。
2. 使用 `payment_log_query` 查询同一订单，核对错误码、日志信息、发生时间与 traceId。仅在日志明确提供时说明超时持续时间。
3. 综合两项查询与本手册说明直接可见的失败原因，并明确尚未核实的渠道状态；不要将推测写成事实。

## 处理建议

先按订单号及 traceId 核对支付网关/渠道最终交易状态与对账结果，保留日志并排查链路延迟。状态未明确前不要直接再次扣款；确认未支付后再按业务幂等规则处理重试。若已扣款但订单未更新，应进入补单或人工核对流程，避免重复支付。

本手册不包含任何特定订单的查询结果，也不表示本系统已接入外部支付渠道或具备自动补单能力。
